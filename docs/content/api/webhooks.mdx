# Webhooks

Afriex sends webhook notifications for key events. The SDK validates signatures and triggers test events in sandbox.

## Setup

Pass your webhook public key during initialization:

```typescript
const afriex = new AfriexSDK({
  apiKey: "your-api-key",
  webhookPublicKey: "your-afriex-public-key",
});
```

## Verify and Parse

Validate signature and parse payload in one call:

```typescript
app.post("/webhook", (req, res) => {
  const signature = req.headers["x-webhook-signature"];
  const payload = req.body; // Raw string body

  try {
    const event = afriex.webhooks.verifyAndParse(payload, signature);

    switch (event.event) {
      case "CUSTOMER.CREATED":
      case "CUSTOMER.UPDATED":
      case "CUSTOMER.DELETED":
        console.log("Customer created:", event.data);
        break;
      case "TRANSACTION.CREATED":
      case "TRANSACTION.UPDATED":
        console.log("Transaction created:", event.data);
        break;
      case "PAYMENT_METHOD.CREATED":
      case "PAYMENT_METHOD.UPDATED":
      case "PAYMENT_METHOD.DELETED":
        console.log("Payment method created:", event.data);
        break;
      case "CHECKOUT_SESSION.CREATED":
        console.log("Checkout session created:", event.data);
        break;
      case "POOL_DEPOSIT_REQUEST.REJECTED":
        console.log("Pool deposit rejected:", event.data);
        break;
    }

    res.status(200).send("OK");
  } catch (error) {
    console.error("Invalid signature");
    res.status(400).send("Invalid signature");
  }
});
```

## Verify Only

Validate signature without parsing:

```typescript
const isValid = afriex.webhooks.verify(payload, signature);

if (isValid) {
  const event = JSON.parse(payload);
  // Handle event
}
```

## Trigger Test Webhook (Sandbox)

Send a test webhook to your endpoint in sandbox:

```typescript
const result = await afriex.webhooks.triggerTestWebhook({
  event: "TRANSACTION.UPDATED",
  entityId: "transaction-id",
});

// Check your webhook endpoint for the test event
console.log(result.data);
// { queued: true, event: 'TRANSACTION.UPDATED', entityId: 'transaction-id',
//   deliveryUrl: 'https://your-endpoint.example.com/webhooks' }
```

For `CHECKOUT_SESSION.CREATED`, use the checkout session UUID as `entityId`.

`resourceId` is accepted as a **deprecated** alias for `entityId` — it still works (mapped to `entityId` before the request is sent, since that's the field name the API accepts), but logs a deprecation warning and will be removed in a future version. Use `entityId`.

**Supported Events:**

| Event                      | Resource Type         |
| :------------------------- | :-------------------- |
| `CUSTOMER.CREATED`         | Customer ID           |
| `CUSTOMER.UPDATED`         | Customer ID           |
| `CUSTOMER.DELETED`         | Customer ID           |
| `TRANSACTION.CREATED`      | Transaction ID        |
| `TRANSACTION.UPDATED`      | Transaction ID        |
| `PAYMENT_METHOD.CREATED`   | Payment Method ID     |
| `PAYMENT_METHOD.UPDATED`   | Payment Method ID     |
| `PAYMENT_METHOD.DELETED`   | Payment Method ID     |
| `CHECKOUT_SESSION.CREATED` | Checkout Session UUID |

## Event Types

### Customer Events

| Event              | Description      |
| :----------------- | :--------------- |
| `CUSTOMER.CREATED` | Customer created |
| `CUSTOMER.UPDATED` | Customer updated |
| `CUSTOMER.DELETED` | Customer deleted |

**Payload:**

```typescript
{
  event: 'CUSTOMER.CREATED',
  data: {
    customerId: string,
    name: string,
    email: string,
    phone: string,
    countryCode: string,
    meta?: Record<string, unknown>,
    createdAt?: string,
    updatedAt?: string
  }
}
```

`CUSTOMER.DELETED` carries the same full object: the customer's last known
state. There is no slimmed-down delete payload and no `deletedAt` field.

### Transaction Events

| Event                 | Description                |
| :-------------------- | :------------------------- |
| `TRANSACTION.CREATED` | Transaction created        |
| `TRANSACTION.UPDATED` | Transaction status changed |

**Payload:**

```typescript
{
  event: 'TRANSACTION.UPDATED',
  data: {
    transactionId: string,
    customerId: string,
    sourceId?: string,
    destinationId: string,
    status: 'PENDING' | 'PROCESSING' | 'SUCCESS' | 'FAILED' | 'CANCELLED' |
            'REFUNDED' | 'RETRY' | 'UNKNOWN' | 'SCHEDULED' |
            'CUSTOMER_ACTION_REQUIRED' | 'REJECTED' | 'IN_REVIEW' | 'RFI_REQUESTED' |
            'DISPUTED' | 'DISPUTE_RESOLVED' | 'DISPUTE_WON' | 'DISPUTE_LOST' |
            'DISPUTE_EVIDENCE_SUBMITTED',
    type: string,
    channel?: string,
    merchantReference?: string,
    sourceAmount: string,
    sourceCurrency: string,
    destinationAmount: string,
    destinationCurrency: string,
    rate?: string, // 1 sourceCurrency = rate destinationCurrency
    fee?: string,  // in sourceCurrency; omitted when no fee applied
    meta: { idempotencyKey?, reference?, narration?, invoice?, failureReason? },
    createdAt: string,
    updatedAt: string
  }
}
```

### Payment Method Events

| Event                    | Description            |
| :----------------------- | :--------------------- |
| `PAYMENT_METHOD.CREATED` | Payment method created |
| `PAYMENT_METHOD.UPDATED` | Payment method updated |
| `PAYMENT_METHOD.DELETED` | Payment method deleted |

**Payload:**

```typescript
{
  event: 'PAYMENT_METHOD.CREATED',
  data: {
    paymentMethodId: string,
    channel: string,
    customerId: string,
    accountName: string,
    accountNumber: string,
    countryCode: string,
    status?: 'active' | 'pending' | 'deleted' | 'expired' | 'blocked',
    institution: { institutionId?, institutionName?, institutionCode? },
    recipient: { recipientName?, recipientEmail?, recipientPhone? }
  }
}
```

### Checkout Session Events

| Event                      | Description              |
| :------------------------- | :----------------------- |
| `CHECKOUT_SESSION.CREATED` | Checkout session created |

**Payload:**

```typescript
{
  event: 'CHECKOUT_SESSION.CREATED',
  data: {
    sessionId: string,
    merchantReference: string,
    amount: number, // minor units
    currency: string,
    expiresAt: string,
    createdAt?: string,
    afriexTransactionId?: string, // once paid
    paidAt?: string,              // once paid
    metadata?: Record<string, string>,
    customer?: { name?, email?, phone?, countryCode? }
  }
}
```

<Callout type="warn">
  This event fires when the session is created. It is not a payment signal.
  Follow `TRANSACTION.UPDATED` on the transaction the session produces.
</Callout>

### Pool Deposit Events

| Event                           | Description                                         |
| :------------------------------ | :-------------------------------------------------- |
| `POOL_DEPOSIT_REQUEST.REJECTED` | A submitted pool-account deposit was rejected in review |

**Payload:**

```typescript
{
  event: 'POOL_DEPOSIT_REQUEST.REJECTED',
  data: {
    transactionId: string,
    reference: string,
    amount?: number,
    currency?: string,
    rejectionReason: string,       // free text; do not branch on it
    resubmissionRequired: boolean  // true: correct and resubmit; false: final
  }
}
```

An approved deposit arrives as `TRANSACTION.CREATED`.
